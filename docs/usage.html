DSH 云同步 · 使用说明

把 DeepSeek Harness 的会话、附件、工作区索引、任务板，逐目录增量镜像到阿里云盘；换台电脑拉回来就能接着用。

插件版本 0.5.3 密钥信封同步主链路插件内更新附带包解码器一主多从

1三十秒看懂

只有两条链路：同步（搬数据）和解码（开旧包）。同步是明文镜像，不走加密。

同步 主链路

把 ~/.dsh 里选中的 4 个（或更多）目录按文件推到云端；云端就是原始目录树，不用口令。换台电脑拉回来即可。

解码 兼容

0.4.0 起不再打包加密上传。旧的 payload.enc 或别人分享的包，仍可在页面里校验、解包。

一分钟版本装插件 → aliyunpan login → 勾目录 → 「开始同步」上传 → 另一台同样装插件、登录、点「从机拉取」。

2一次性准备

每台电脑都要做一遍：装命令行工具、登录、装插件。

2.1 装 aliyunpan 并登录

插件不实现阿里云盘协议，只调用官方 CLI。两条路，任选一条：

配置页「运行环境」→ 下载并安装（推荐）→ 自动装进 tools\

自举安装：插件找不到 CLI 时，卡片和配置页都会出现「下载 aliyunpan」按钮。点一下就完成：查官方 release → 按平台/架构挑包 → 下载校验 → 解压到插件数据目录 tools\ → 跑 --version 试跑 → 把路径写进配置。免安装、不写注册表、不要管理员权限。下载不通（大陆网络常见）分三层兜底：① 官方直连失败会自动依次试镜像 ghfast.top、gh-proxy.com（只对 github.com 地址生效），每个源重试 2 次，日志逐条写清失败原因（如 UND_ERR_CONNECT_TIMEOUT）；② 用浏览器/迅雷下好 zip，在配置页「下载不了？」里点「选文件…」→「从本地安装」，完全离线；③ 内网文件服务器就把 zip 直链填进「自定义地址」。

也可以手动装：解压到任意目录，或放进 PATH（插件会自动在 PATH 里找）。

aliyunpan who          # 看当前登录的账号（UID / 昵称 / 网盘）
aliyunpan ls "/"       # 能列目录就算通了

登录不用敲命令行，见下一节「2.2 登录阿里云盘」。

注意不要把 aliyunpan 装在需要管理员权限才能读的目录，否则插件以普通用户启动子进程时会找不到。

2.2 登录阿里云盘（0.5.1 起，页面里点）

两台电脑必须是同一个阿里云盘账号。不是的话，从机看到云端就跟空的一样（旧版本的直接后果是 11 个根全「云端还没有这个目录，跳过」）。

配置页「阿里云盘账号」卡 → 登录阿里云盘→ 浏览器点「允许」+ 手机 APP 扫码→ 我已扫码，继续
  1. 打开完整配置页，最上面的「阿里云盘账号」卡显示已登录（昵称 + UID 前 8 位）或未登录。
  2. 点〔登录阿里云盘〕，等几秒，卡里出现授权链接（https://openapi.alipan.com/oauth/authorize…）。
  3. 点〔打开链接〕（拦弹窗就用〔复制链接〕粘到浏览器）→ 点「允许」→ 跳到二维码页 → 手机阿里云盘 APP 扫码。
  4. 回到配置页点〔我已扫码，继续〕（等于给 aliyunpan login 敲回车）→ 状态变「已登录」。
  5. 链接 5 分钟有效。过期就〔取消〕，再点一次〔登录阿里云盘〕。
失败也返回 0aliyunpan login 失败时退出码也是 0，所以插件靠两件事判断成功：输出里出现「登录成功」，或登录后再跑 aliyunpan who 能拿到 UID。都没拿到就报「登录没有完成」。

2.3 装插件

dsh plugin --profile desktop add github:LYF-12/dsh-aliyunpan-backup

命令行安装不会自动登记 bundle：打开 ~/.dsh/profiles/desktop/package.json，确认 dsh.profile.bundles 数组里有 dsh-aliyunpan-backup，没有就手动加一行。装完重启 DSH。

2.4 认识界面

设置 → 插件 → 本插件是一张卡片：状态、上次结果、四个按钮；缺 aliyunpan 时多一个「下载 aliyunpan」。

同步上传· 从机拉取· 刷新· 打开完整配置页

完整配置页里八张卡：阿里云盘账号、运行环境、插件更新、同步、解码本地包、口令、路径配置、解码日志。第一次用建议先开完整配置页做设置。

插件卡片上也会多一行账号状态；未登录时按钮里多一个〔去登录〕（直接就地展开配置页）。

卡片上的状态徽标只反映同步这条链路：未同步 → 同步中 → 已上传 / 已拉取。看到「未同步」不等于插件坏了，点一次「同步上传」就开始。缺 CLI 时徽标是「缺 aliyunpan」，右侧会多一个「下载 aliyunpan」。

路径不用手打配置页里每个路径框右边都有「浏览…」，点开是 Windows 原生选择框，选完自动回填。也可以继续手填。

3上传：本机 → 云端

把本机数据推到云端。第一次是全量，之后只传变化的文件。

选目录 + 装配文件

同步卡片里勾选要传的目录。默认四个：sessions（会话）、attachments（附件）、storages（工作区/定时/索引）、task-board（任务板）。还可以加 skins、pets、eda、sources、backups、dsh-usage。

下面还有三个文件级选项：模型与插件装配（profiles/<profile>/cordis.patch.yml，模型列表在这里）、插件清单（package.json + 锁文件）、登录凭据（.credentials.yaml，默认不勾）。API Key 不在模型配置里，要带走 Key 得单独勾「登录凭据」（明文上云），或者勾「加密同步登录凭据（密钥信封）」走密文（见下面的密钥信封）。

预演

点「预演」只做统计：多少个文件、多少 MB、云端目标路径。不动云端也不动本机。心里有数再传。

开始同步（upload 模式）

新增文件走 --skip（云端同名跳过），修改文件走 -ow 覆盖，无变化直接跳过。按云端父目录分批、每批 ≤20 个、4 并发。

看结果

每个目录一行：OK 上传 N 个文件 用时 Ns。末行固定 SYNC RESULT: mode=upload roots=N files=N failed=0。失败数非 0 就看下面的同步日志。

云端长什么样

/DeepSeek Harness/DSH-Sync/
  sessions/      # 每个会话一个 .jsonl.zstd
  attachments/   # 按 sha256 分桶的对象文件
  storages/
  task-board/
  _last-sync-A.json   # 本机留痕，供其它机器判断谁最近同步过
为什么只传变化的部分本地 sync-index.json 记着每个文件的 size + mtime。比对出新/改/不变，分别处理。索引丢了会自动退回全量覆盖，不会漏内容。

凭据：密钥信封（可选，0.5.3 起）

想连 API Key 一起带到另一台机器，又不想明文上云：勾「加密同步登录凭据（密钥信封）」。插件用 keyFile 里的口令把 .credentials.yaml 加密成 .credentials.yaml.enc 再上传，云端只有密文；勾上后明文「登录凭据」那一项自动置灰。

不开信封开信封（credentialsEnvelope: true）
云端文件DSH-Sync/.credentials.yaml（明文）DSH-Sync/.credentials.yaml.enc（AES-256-GCM）
换机器还原下下来就是明文必须同一个口令，解出写回 ~/.dsh/.credentials.yaml
口令丢了不影响那个信封永久打不开（Key 仍在本机）
两台机器必须同一个口令口令存在 KEY.txt，不随同步上传。新机器在配置页「口令（KEY.txt）」里粘贴主机那串，再拉取。口令错只会报「口令不对（或信封被改过），解密失败」，不会写坏本机凭据；本机已有不同内容会先备份成 .credentials.yaml.bak-<时间戳>。
# 命令行等价
node lib/scripts/syncd.mjs --mode upload     # 加密并上传 .credentials.yaml.enc
node lib/scripts/syncd.mjs --mode download   # 下载密文并解密写回 .credentials.yaml

4拉取：云端 → 本机

把云端的改动拉回本机。默认只增不删，覆盖同名文件。

先退出 DSH

正在运行的 DSH 握着会话文件与锁文件，Windows 上写入会被拒。要么退出应用，要么只拉不覆盖（默认只增不删仍可能碰到同名文件）。

点「从机拉取」

切到 download 模式执行。先把云端目录下到暂存目录 syncDlDir（留空 = 插件数据目录下 sync-dl），再由插件逐文件镜像进 ~/.dsh。

看结果

OK 下载 N 更新 N 未变 N。默认不删本机多余文件；勾了 拉取时删除本机多余文件 才是严格镜像（会删）。

为什么不让 CLI 直接写 ~/.dshCLI 会自己多建一层 DeepSeek Harness\DSH-Sync\ 目录，路径就错了；而且只有逐文件比对才能做到只写变化的部分。所以中间加了一层暂存目录。

装配文件的 profile 名（0.5.2 起自动发现）

模型配置与插件清单是 profiles/<profile>/ 下的文件。从机不再假设云端叫本机那个名字：拉取前先 ls 云端 profiles 目录，拿到真实名字再拼路径，日志会打 [info] 云端 profile: desktop、web。

云端本机落到哪里
desktop有 desktop原样，profiles/desktop/
只有 desktop只有 soloprofiles/solo/（两边都只有一个，1:1 映射）
desktop + web只有一个或没有按云端名各建目录，不合并

多个云端 profile 不做合并：往同一个本机文件写两份会互相覆盖，宁可各建各的目录。

严格镜像（可选）

勾选 syncPrune（配置键 syncPrune: true）后，本机比云端多出来的文件会被删除，两边完全一致。适合「从机只读，不产生自己的数据」的用法。第一次开之前先备份。

5另一台电脑怎么用

新机器只有三步：装插件、登录云盘、拉取。

5.1 标准流程

# 1) 装 aliyunpan 并登录
aliyunpan login

# 2) 装插件（同版本 DSH 更稳）
dsh plugin --profile desktop add github:LYF-12/dsh-aliyunpan-backup

# 3) 确认 bundle 已登记，然后重启 DSH
#    设置 → 插件 → 阿里云盘同步 → 从机拉取

5.2 拉取前后

时机做什么为什么
拉取前退出 DSH会话/锁文件被占用，写入会被拒
拉取后启动 DSH，检查工作区列表与会话工作区路径是绝对路径，A 机的路径在 B 机上可能不存在
首次在 B 机上做一次「同步上传」为空跑建立本地索引，之后拉取才按增量走
路径不一致怎么办storages/workspace.json 里存的是工作区的绝对路径。B 机上如果路径不同，DSH 里对应的会话会显示为不可用，手动重新添加工作区即可，不影响会话内容本身。

5.3 不要两台同时传

同步没有合并逻辑：同一文件两边都改，后传的覆盖先传的。约定一台主机推、其它只拉最省心。插件会在 syncLockMinutes（默认 60）内检测到其它机器的活动并告警。

6解码加密包

0.4.0 起不做打包上传了，但旧包和别人的包仍然能开。

选择 payload.enc 或包目录→ 检查这个包→ 校验完整性→ 解包到独立目录

6.1 包的结构

<包目录>/
  payload.enc        # DSHBK002 容器：36B header + 每 1MiB 一块 tag16|ciphertext
  package.info.json  # 明文：createdAt / fileCount / totalBytes

AES-256-GCM 分块，密钥由 scrypt(口令, salt, 32) 派生，AAD 为 dshbk-chunk-<i>。明文是 DSHBUNDLE1 容器，内含每个文件的 sha256 清单。

6.2 两种操作

按钮做什么输出
校验完整性逐块解密 + 逐文件比 sha256，不落盘verify: ok=N bad=0 missing=0
解包解密后写到输出目录，附 RESTORE-manifest.jsonextracted=N

解包不会覆盖 ~/.dsh：默认落到 restore\<包名>，自己挑需要的文件拷回去。

6.3 解别人分享的包

「口令」栏留空 = 用本机 KEY.txt；解别人的包时直接在解码卡片的 口令 输入框里填对方给的口令即可，不会写盘、也不会覆盖你自己的口令。

6.4 换电脑开旧包

aliyunpan ls "/DeepSeek Harness/DSH-Backup/snapshots"
aliyunpan download --saveto "D:\DSH-Backup\snapshots" "<云端路径>"
# 然后：解码本地包 → 检查 → 校验 → 解包
退出码含义
0成功
2缺参数（--pkg / --out）
3不是 DSHBK002 容器
4AUTH FAIL at chunk N：口令错或包损坏
5明文不是 DSHBUNDLE1
6校验失败（有 bad / missing）

7多机与换机注意

一主多从

一台负责推，其它只拉。多台都推会互相覆盖。

锁与留痕

每台写 _last-sync-<机器名>.json；syncLockMinutes 内检测到别家活动会告警，--strict 下直接退出。

DSH 版本

两台用相近版本的 DSH，会话与索引格式才兼容。

隐私

同步是明文，云端目录可以直接打开。附件里有隐私内容时慎选目录。

不要对同一份数据同时开同步与旧备份上传旧版 0.3.x 的打包链路已移除；如仍有旧客户端在跑，注意它们不共享索引，会互相覆盖文件。

7+更新插件

插件自己会看有没有新版本，点一下就更新，不用再去命令行或插件市场。

有新版本时

设置 → 插件 → 本插件卡片的按钮行会多一个「更新插件到 0.5.0」。点它：查上游版本 → 下载源码包 → 解压 → 整目录替换。旧目录先改名成 xxx.old-时间戳，失败自动换回来。

更新完要重启 DSH

卡片会显示「已更新到 x，重启 DSH 生效」。宿主那半边的代码已经在内存里了，不重启还是旧逻辑。重启前别正在同步，会掐断。

没有新版本时

按钮是「检查插件更新」，点了就是重新查一次上游。

完整配置页的「插件更新」卡能看到：当前版本、磁盘上的版本、上游版本、安装位置（多个 profile 会列出哪个正在用）、实时更新日志。下载走「官方直连 → ghfast.top → gh-proxy.com」+ 每源 2 次重试，和装 aliyunpan 用的是同一套下载器。

两种安装方式都能更新：github: 装的是真实目录 → 整目录替换；link: 指向 git 工作副本 → 改走 git pull --ff-only（目录里没有 .git 会提示你手动拉）。

为什么不用 pnpm 重装：那要求目标机器上有 pnpm、会改 profile 的锁文件、还会往全局 store 写 hardlink。本包零运行时依赖，换一份文件与重装等价。

9常见问题

从机拉取，11 个根全是「云端还没有这个目录/文件」

先看配置页「阿里云盘账号」：是不是已登录、昵称和 UID 与主机一致。没登录时 aliyunpan download 会 panic，旧版本把它当成「云端没有」静默跳过，于是 files=0 却 failed=0（0.5.1 起直接 exit 4 并提示先登录）。账号没问题，再核对 syncDir 是否与主机一致、主机是不是真上传过（aliyunpan ls "/DeepSeek Harness/DSH-Sync"）。

上传很慢 / 一直 0 个文件

0 个文件 = 索引显示无变化。想强制重传，删掉插件数据目录下的 sync-index.json 再同步（会走全量覆盖）。慢通常是云盘限速，不是插件。

日志里出现 Access is denied

安全软件拦了 aliyunpan.exe 写盘。把 syncDlDir 换到它允许的目录（例如开发目录），或给 exe 加白。日志里会有 [hint] 提示。

云端出现 name(1).ext 副本

同一次上传里同名文件重复且没走 --skip。本插件新增走 --skip 不会产生副本；若已经产生，删掉副本再同步一次。

拉取后 DSH 里的工作区不见了

storages/workspace.json 里是绝对路径，换机后路径不存在。重新添加工作区即可，会话内容还在。

解包报 AUTH FAIL at chunk 0

口令错（或包损坏）。注意口令区分大小写、前后不要带空格。别人分享的包要在解码卡片里填口令，不是本机 KEY.txt。

还能不能加密上传

0.4.0 起没有打包上传入口。要加密留档，可以自行打包后放云盘，再用解码器打开；同步链路本身是明文。

两台电脑都点上传了

后传的覆盖先传的。没有自动合并。恢复办法：从另一台再拉一次，或用文件历史/云盘回收站找回。
